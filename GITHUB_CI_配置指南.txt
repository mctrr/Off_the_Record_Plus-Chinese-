双仓同步 + 自动发行 使用说明
============================

仓库
----
  GitCode  https://gitcode.com/Fallend/Off_the_Record_Plus
  GitHub   https://github.com/mctrr/Off_the_Record_Plus-Chinese-

  两边的发行版是同一份产物，附件字节完全相同。


整体模型
--------
  本地 work/ 目录是唯一真身。
  GitCode 与 GitHub 都只是镜像。

  推一个 v* tag → GitHub Actions 自动：
    1. 在 windows-latest 上跑 build.py（原生跑 BCS_TXT.exe）
    2. 校验 zip 里带 data/frontend/str_en.bcs（解压到游戏根目录即装好）
    3. 建 GitHub 发行版
    4. 建 GitCode 发行版
    5. 把 main 与 tag force 镜像回 GitCode

  不需要本地打包，不需要手动传附件。


发布新版本
----------
  1. 改 build.py 顶部的 VERSION，例如：
         VERSION = '1.2'

  2. 提交并打 tag（tag 名 = v + VERSION，必须一致）：

         cd "C:/Users/123/WorkBuddy/汉化/Off_the_Record_Plus-Chinese-/work"
         git add -A
         git commit -m "release: v1.2"
         git tag v1.2

  3. 推到 GitCode（本机 git push GitHub 会 408，见下文）：

         BASIC=$(printf 'Fallend:%s' "$GITCODE_TOKEN" | base64 -w0)
         git -c http.https://gitcode.com/.extraheader="Authorization: Basic $BASIC" \
             push origin HEAD:refs/heads/main
         git -c http.https://gitcode.com/.extraheader="Authorization: Basic $BASIC" \
             push origin refs/tags/v1.2:refs/tags/v1.2

  4. 推到 GitHub（用脚本，不用 git push）：

         GH_PAT=ghp_xxx python ../../.tools/gh_push_api.py
         GH_PAT=ghp_xxx python ../../.tools/gh_sync_tags.py

     gh_push_api.py 会把工作区与本地 HEAD 推上去，并核对 tree sha 一致；
     gh_sync_tags.py 把所有本地 tag 打到 GitHub 的 main head 上。

  5. GitHub Actions 里「发布」会自动跑。跑完两端都有 v1.2。

  ⚠️ VERSION 与 tag 必须一致，否则「发布」会走「非当前版本，跳过」分支，不出包。
     这是有意的：镜像历史 tag 时不该重新出包。


附件命名
--------
  GitCode：丧尸围城2绝密档案Plus-汉化补丁-v1.2.zip（中文名正常）
  GitHub ：DR2-OTR-Plus-CHS-v1.2.zip

  GitHub 的 uploads API 不接受非 ASCII 文件名——传中文名会落成 default.zip，
  传中文全名直接 422。所以 GitHub 那边固定用 ASCII 名，
  中文版本信息放在发行版标题里。


已踩过的坑（别再重复）
----------------------
  GitCode
    - 令牌走 ?access_token= query 参数，Authorization 头一律 401
    - 更新发行版必须 PATCH /releases/<tag>，PUT 返回 404
    - Release 对象没有 id，只能按 tag 定位
    - 附件上传三步：GET upload_url → PUT 预签名地址（headers 原样带回）
    - 令牌会静默失效：API 和 git 写全 401，但只读克隆照常，
      所以「能 clone」不代表令牌活着。测法：curl 一下 API 和 git-receive-pack

  GitHub
    - git push 恒定 HTTP 408（postBuffer / HTTP1.1 / 代理都试过，无效），
      只能走 REST API：blobs → trees → commits → PATCH refs
    - 必须用 base_tree 且 parents 指向远端 main，否则推成孤儿快照
    - git ls-files 要加 -c core.quotepath=false，否则中文路径变八进制转义
    - Windows 上所有文件按 100644 记，别用 os.access(X_OK) 猜
    - uploads API 不吃中文附件名（见上）
    - POST /releases 的响应里 assets 恒为空；DELETE 是异步的，
      删完要轮询到列表清空再传同名文件

  Windows runner
    - build.py 一 print 中文就 UnicodeEncodeError（cp1252）。
      PYTHONIOENCODING 对管道 stdout 无效，必须在脚本里
      sys.stdout.reconfigure(encoding='utf-8')（build.py 已内置）

  本地
    - git push 可能静默超时（exit 0 但远端没变），
      必须在新开的 shell 里 ls-remote 复核
    - refs/remotes/origin/* 每次操作后消失，
      比较时用 ls-remote 或显式 fetch 到 refs/remotes/origin/main


手动补发某个版本
----------------
  GitHub Actions → 发布 → Run workflow → tag 填 v1.2 → Run
  （build.py 的 VERSION 必须等于该 tag，否则会跳过）


恢复被覆盖的旧历史
------------------
  两边的历史已按「本地为准」force 过，旧历史不再可达。
  文件内容没有丢——每次 force 推的都是完整快照。
