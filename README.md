# 丧尸围城2：绝密档案 Plus — 简体中文文本表

把 **Off the Record Plus** 模组的界面 / 对白文本换成简体中文。
以 3DM 蒹葭汉化组的原版汉化补丁做底本，按 Plus 模组新增的文本逐条补齐、逐条校对。

## 版本

当前版本：**0.2a**（tag `v0.2a`）

## 仓库里有什么

| 文件 | 说明 |
|---|---|
| `新的汉化补丁.txt` | **成品**。12832 条全量中文文本表，装游戏用的就是这个 |
| `str_en.txt` | 模组英文原表（12832 条）。当对照用，同时是 ID / `[@按键]` / 色码 / `%s` 占位符的来源 |
| `原汉化补丁.txt` | 3DM 蒹葭汉化组的原版汉化补丁（8071 条）。做底本用，也是术语的基准 |
| `BCS_TXT.exe` | 打包工具。把 txt 编译成游戏读的 `str_en.bcs` |
| `名词替换` | 专名对照表 |
| `build.py` | 构建脚本。体检 + 打包 + 往返复核 + 出 `build/` 发布包 |
| `g.sh` | 速查脚本。见下面的「常用命令」 |

`.bcs` 二进制不入库，由 `BCS_TXT.exe` 从 `新的汉化补丁.txt` 生成。

## 怎么用

1. 装 Off the Record Plus 模组
2. 下发行版里的 zip，**整个解压到游戏根目录**，提示「替换文件」选「是」
3. 进游戏

zip 里已经带好 `data/frontend/str_en.bcs` 的完整路径，解压就落到正确位置，
不用自己挪文件。游戏目录在哪：Steam 里右键游戏 → 管理 → 浏览本地文件。

**还原成英文**：把模组自带的 `str_en.bcs` 拷回去，或 Steam 里校验文件完整性。

## 常用命令

装个 Git for Windows / 用 Git Bash：

```bash
sh g.sh p      # 开工前自检：工作区干不干净、ID 序列对不对、行尾有没有被改
sh g.sh s      # 看未提交改动
sh g.sh g      # 最近提交
sh g.sh d      # 某次提交改了哪些 ID
python build.py            # 体检 + 打包 + 出 build/ 发布包
python build.py --check    # 只体检，不打包
python build.py --install  # 再额外部署到游戏目录（覆盖前自动备份）
```

`build.py` 会做这些检查，任何一项硬伤没过就中止，不会打出坏包：
BOM / 纯 CRLF / ID 序列与英文表一致 / UTF-8 可解码 / 非法控制字节 /
`[@按键]` 取值 / 色码 / `%s`%d` 占位符 / `\0A` 断行 / placeholder 标记行，
外加字形覆盖与长行宽度。打包后**解包回读逐字节比对**，一致才覆盖 `.bcs`。

改版本号只改 `build.py` 顶部的 `VERSION`，zip 文件名和安装说明会跟着变。

## 文本表约定

- UTF-8 带 BOM、CRLF。文件内所有 ID、按键引用 `[@xxx]`、颜色码、`%s`/`%d`
  占位符都与英文原表严格一一对应。
- 换行用 `\0A`。面板 / 对白 / 播片字幕的框宽不一样，**断行是逐条读出来切的，
  不是按字符数硬截**——中文不像拉丁字母能靠空格自动折行，截错了就掉字或出框。
- 仓库里的三个 txt 已用 `.gitattributes` 钉死 `-text`，禁止 git 做换行转换。
  换行被归一化后，文件就不再和打包链路一致了。**改这几个文件时别去掉这行。**
- 仍有少量条目保持英文（专名、按键名、缩写），属预期。
